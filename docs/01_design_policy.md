# 1. 教材設計方針

## 1.1 目的と対象

| 項目 | 内容 |
|---|---|
| 学習対象 | Python（動作確認: Python 3.12.10。3.10 以上で同じ結果になる内容のみ使用） |
| 対象者 | プログラミング未経験者・初心者 |
| 到達目標 | 基本構文を理解し、短いプログラムを読み、自分で書けるようになる |
| 学習サイクル | 短い教科書（各ステージ2セクション、1セクション約2〜3分）を読む → その場で問題を解く → 解説で理解する |
| 規模 | 10ステージ × 10問 = 全100問（`PY-001`〜`PY-100`） |
| 実行環境 | ブラウザで動くWebアプリ（日本語） |

## 1.2 設計原則（指示書の設計思想への対応）

| 設計思想 | 教材での実現方法 |
|---|---|
| 短時間で終わる | 1ステージ＝レッスン2セクション（各2〜3分）＋10問。1ステージ約15〜25分を想定 |
| 日常的な言葉 | 各セクションに用語解説を設け、「変数＝値に付けた名前」のように言い換える |
| つまずきの先回り | 各ステージに「よくある間違い」（誤ったコード・理由・直し方）を4件ずつ載せ、問題の誤答選択肢もそこから作成 |
| 読んで考える問題 | 実行結果の予測（38問）、間違い探し（20問）で「読む力」を重視 |
| 学びにつながるフィードバック | 全問に、正解後・不正解後の短いメッセージ、正解の根拠、詳しい解説を用意。選択式は**選択肢ごとの誤りの理由**、入力式は**よくある誤答と理由**を用意 |
| 知識の再利用 | 例: 境界値（ステージ3の60点以上）→ ステージ4 range → ステージ9 おみくじ・4文字以上 → ステージ10 回文・集計に繰り返し登場 |
| 難易度の段階化 | ステージ平均難易度 1.1 → 1.7 → 2.2 → 2.7 → 2.3 → 3.3 → 3.4 → 3.3 → 3.3 → 4.3（ステージ5は新しいデータ型の導入のため一度下げている） |
| 難しすぎる内容は避ける | クラス・ファイル操作・内包表記・input() などは扱わない（下記「扱わないこと」） |
| 正確性優先 | すべてのコードを実際に実行して検証（検証レポート参照） |

## 1.3 出題形式の方針

- 学習初期は選択式を多く、後半は入力・コード作成を増やす。選択式（choice）の問題数はステージ順に 6 / 5 / 5 / 4 / 5 / 6 / 5 / 4 / 5 / 3、コード作成は各ステージ1問（ステージ10のみ4問）。
  - 注意: 新しいデータ型や概念を導入するステージ（5・6）では、あえて選択式を増やしている。そのため「選択式が単調に減る」設計にはなっておらず、**緩やかな減少傾向**にとどまる（検証レポートの「残るリスク」にも記載）。
- 出題形式は5種類: `multiple_choice`, `predict_output`, `fill_blank`, `bug_fix`, `code_write`。
- `predict_output` と `bug_fix` は、`answer_mode` により **選択式（choice）** と **入力式（text）** の両方がある。
- 配分の実績（全100問）: 3択選択 18 / 実行結果予測 38 / 穴埋め 11 / 間違い探し 20 / コード作成 13。

## 1.4 仮定（確認質問で止まらず、置いた仮定）

1. 環境は PC のモダンブラウザ。モバイルでの長いコード入力は想定しない（穴埋めや選択式を多めにしてある）。
2. `input()` は使わない。ブラウザの試作で標準入力のUIを作らずに済ませ、採点を決定的にするため。入力値は変数や関数の引数で与える。
3. 乱数は ステージ9 の `random.randint` の理解（範囲）に限定して扱い、**乱数の値に依存する採点はしない**。
4. 学習者は半角・全角を区別する習慣がまだない。採点では NFKC 正規化で全角→半角を許容する。ただし文字列内部の空白は変更しない。
5. クリア条件は「1回目の回答で7問以上正解」。この値は調整可能な設定値で、`curriculum.json` に格納してある。
6. 動作確認は Python 3.12.10 のみ。3.10・3.11・3.13 では**未実行**（使用機能はいずれも 3.10 以降で安定したものに限定）。
7. 検証用のコード実行は、ローカルの教材検証専用。学習者のコードを実行する本番環境の安全要件は「採点仕様」で別途定義する。

## 1.5 扱わないこと（スコープ外）

`input()`、ファイル入出力、クラス・オブジェクト指向、内包表記、ラムダ式、`*args`/`**kwargs`、`global`、集合・タプルの本格的説明、`is` と `==` の違い、f文字列の書式指定、`with`、標準ライブラリ（`random.randint` を除く）、拡張スライス `[::-1]`（PY-098 の**別解**としてのみ許容。教科書では教えていない）。

## 1.6 品質基準（問題）

選択肢は原則3つ／正解は必ず1つ／誤答は初心者が実際にする勘違いに基づく／解説は理由まで説明／前のステージの知識のみ使用／コード作成問題は模範解答・別解・不合格例・テストケースを用意。これらは `src/verify.py` と `src/check_scope.py` で機械的にも確認している。
