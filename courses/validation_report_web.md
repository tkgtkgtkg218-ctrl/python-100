## 2. 検証方法

### 2.1 実行確認済み（実際にブラウザで実行して確認）

| 問題の種類 | 確認した内容 |
|---|---|
| 実行結果・表示の予測 | JavaScript は `console.log` の出力を、HTML/CSS は表示の測定値（`getComputedStyle`・`getBoundingClientRect`・`offsetWidth`・`compatMode` など）を取得し、**正解の選択肢と一致**し、**誤答の選択肢とは一致しない**ことを確認。入力式は、よくある誤答が、実際の値と異なることも確認 |
| 穴埋め | 許容回答を**すべて**代入して、期待どおりになるか（出力または式）。よくある誤答を代入して、**期待どおりにならない**こと |
| 間違い探し | 誤りのあるコードが、記載どおりのエラー名・誤った出力・条件を満たさない状態になること。修正後が正しいこと。入力式は、許容する修正行を全部差し替えて正しいこと／誤答を差し替えて誤りになること。選択式で選択肢が「1行の置き換え」のものは、全選択肢を差し替えて、正解だけが正しくなること |
| コード作成（JavaScript 14問・HTML/CSS 10問） | 初期コードが不合格、模範解答が全テスト合格、**別解（JS 18・HTML/CSS 10）が合格**、**不合格例（JS 28・HTML/CSS 20）が不合格**（合計 JS 62・HTML/CSS 61 テスト、うち非公開 37・16） |
| 隔離・制限 | アプリの `#/js/selftest`・`#/htmlcss/selftest`（開発用画面）で、再実行できる |

### 2.2 目視・論理確認のみ（実行していない）

- 解説・根拠・ヒント・フィードバックの、日本語の自然さと内容の正しさ（作成者の通読）。HTML/CSS の仕様に関する説明（例:「main は1ページに1つ」「strong は重要性」「noopener の意味」）は、**一次資料と照合していない**。
- ヒントが答えを示しすぎていないか、難易度（1〜5）の妥当性、並び順と重複の少なさ。
- 読了時間の目安（各セクション2〜3分）。文字数からの推定で、実測ではない。
- 教科書の「よくある間違い」の `wrong_code` のうち、`claims.json` に入れていないもの（説明用の断片）。
- 選択肢の誤答理由のうち、エラー名・表示の仕様を含まない記述的なもの。

### 2.3 外部資料での確認

HTML Living Standard・CSS 仕様・MDN・ECMAScript 仕様との照合は、この作業では**行っていません**。確認できているのは、「Google Chrome で、記載どおりに動作・表示されること」だけです。次のような、ブラウザの実測で初めて分かったことは、実測を根拠にしています。
- `iframe` の `srcdoc` で読み込んだ文書は、`doctype` がなくても標準モードになる → 互換モードの再現には、blob URL で読み込む必要があった。
- 画像ファイルが存在しない `img`（`width` / `height` 属性つき）は、指定した大きさの領域にならなかった（48×24px） → この仕様に依存する出題は、データ URI の画像を使う形に変更。

## 3. 発見した問題と修正

| # | 発見方法 | 問題 | 修正 |
|---|---|---|---|
| 1 | ブラウザ検証 | HTML/CSS ステージ1の「doctype のない文書」の問題が、`srcdoc` では標準モードになり、**誤りのコードが正しく見えてしまった**（採点基盤の問題） | 採点用・プレビュー用の iframe を、blob URL で読み込む方式に変更。以後、`doctype` の有無が、`document.compatMode` に、正しく反映される |
| 2 | ブラウザ検証 | 「画像の表示サイズ」の問題と、教科書の例が、**実測と合わなかった**（存在しない画像は、width / height どおりの大きさにならない） | 問題をデータ URI（1×1 の画像）に変更。例は、属性の確認のみに変更（大きさの断定を削除） |
| 3 | ブラウザ検証 | 表示の測定値が、実行のたびに揺れた（画面外に置いた iframe では、レイアウトの計算が省略されることがある） | iframe を、画面内に透明で置き、読み込み後に、少し待って、レイアウトを確定させてから測定する |
| 4 | ブラウザ検証 | HTML/CSS ステージ7の「コード作成」の不合格例の1つが、**全テストに合格してしまっていた**（不合格例になっていなかった） | 「.lead が太字になっていない」不合格例に差し替え |
| 5 | 作成中の点検 | HTML/CSS ステージ8のコード作成の非公開テストが、`getComputedStyle(...).width`（border-box では、枠線までを含む値）を使っており、**期待値が誤っていた** | 内容の幅を `clientWidth` から求める式に変更 |
| 6 | 構造チェック | JavaScript の問題の題名が1組重複 | 一方の題名を変更 |
| 7 | 構造チェック | 選択式で、**正解が中央の選択肢に偏っていた**（JavaScript: 47問中34問、HTML/CSS: 56問中44問） | データ作成時に、選択肢の並びを、決定的に入れ替えて均等化（JavaScript: 16/16/15、HTML/CSS: 19/19/18）。アプリは、表示時にもランダムに並べる |
| 8 | 通し確認 | 画面操作のテストが、ときどき失敗した | アプリの不具合ではなく、**Chrome が、短時間の大量の `location.hash` の変更を無視する**（200回/10秒の制限）ため。テスト側で、間隔をあけるように修正 |

## 5. 未検証項目

1. **Chrome 以外のブラウザ（Safari・Firefox）・スマホ実機**。特に、(a) iframe 内の無限ループが、親ページを止めないか、(b) blob URL の iframe の読み込み、(c) 既定のスタイル（余白・文字の大きさ）の違いによる、測定値の差。
2. 古いバージョンのブラウザ。JavaScript の、ES2015 以降の書き方が動くことは、Chrome でのみ確認。
3. 画面の拡大率・ブラウザの文字サイズ設定を変えた状態。
4. 実際の学習者による試行（正答率・所要時間・つまずき）、第三者（指導者）によるレビュー。
5. 教科書の読了時間の実測。
6. HTML・CSS・JavaScript の仕様・用語の、一次資料（HTML Living Standard・CSS 仕様・MDN・ECMAScript）との照合。
7. アクセシビリティ（スクリーンリーダーでの読み上げ）の確認。教材の内容として、alt・label・見出し階層を扱っているが、アプリ自体の画面の検証は未実施。
8. 学習者のコードに対する、悪意のある入力（巧妙なコード）への耐性。Worker・iframe の隔離で守っているが、**完全なサンドボックスではない**。メモリを使い切るコードへの対策も未実装。
