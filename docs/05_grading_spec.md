# 5. 自動採点仕様

本仕様は `src/lib.py` の `grade()` を**参照実装**とし、`src/verify.py` で全問に対して実際に動かして確認済みです。Webアプリ側（JavaScript）で再実装する場合は、この仕様と参照実装に従ってください。

## 5.1 採点方式の一覧

| `grading.method` | 対象 | 件数 | 回答の形 |
|---|---|---|---|
| `choice_id` | 3択選択、選択式の予測・間違い探し | 48 | 選択肢ID（`c1`/`c2`/`c3`） |
| `output_compare` | 入力式の実行結果予測 | 20 | 複数行テキスト |
| `accepted_answers` | 穴埋め、入力式の間違い探し | 19 | 空欄ごとの文字列 / 1行の文字列 |
| `test_cases` | コード作成 | 13 | Python コード全体 |

選択肢の**順序は表示時にシャッフルしてよい**（正解は配列番号ではなく ID で判定するため）。

## 5.2 `choice_id`

`answer.correct_choice_id === 選択ID` なら正解。正解は必ず1つ。

## 5.3 `accepted_answers`（穴埋め）

1. 入力を **NFKC 正規化**（全角英数・記号 → 半角）し、**前後の空白のみ**除去する。
2. 空欄ごとに `answer.blanks[i].accepted` のいずれかと**完全一致**すれば、その空欄は正解。全空欄が正解で全体が正解。
3. `quote_insensitive` が `true` の空欄は、`'` と `"` を区別しない。（例: PY-008 で `"Python"` と `'Python'` を同一視）
4. **やってはいけない正規化**: 文字列やコード内部の空白の削除・圧縮。`a + b` と `a+b` が同じ意味でも、**許容リストに両方を明示的に載せる**方式にしている（例: PY-037 の while の更新式は `i += 1` / `i = i + 1` / `i=i+1` など 7 通りを列挙、PY-019 は括弧の位置・空白違いを 16 通り列挙）。
5. 許容リストの正しさは、**各許容回答を実際にコードへ代入して実行し、期待出力になることを機械検証**している。

入力式の間違い探し（`bug_fix` / `text`）は、`answer.target_line` の1行を学習者の入力で置き換える。インデントは画面側で固定し、入力は行の中身のみ。`answer.accepted` との照合は穴埋めと同じ。

> 発展（試作後に推奨）: 空白の揺れが原因の誤判定を減らすため、`accepted_answers` に不一致のときだけ、「置換後のコードを実行して `answer.expected_output` と一致するか」で再判定する第2段階を追加できる（Pyodide 実行時）。本データの範囲では未実装・未検証。

## 5.4 `output_compare`（実行結果の予測）

比較前に、回答と `answer.expected_output` の両方に次を適用する。

1. 改行コードを `\n` に統一（CRLF/CR → LF）
2. **各行の末尾の空白**を除去
3. 末尾の空行を除去

行頭の空白・行内の空白・大文字小文字・全角半角は**区別する**（出力は `print` の結果そのものを問うため）。数値は文字列として比較する（`5.0` と `5` は別。この区別を学ぶ問題がある）。引用符を含む出力（リストの表示 `['青', '緑']` など）は、そのまま入力する必要があるため、問題文で明示してある。

## 5.5 `test_cases`（コード作成）

### 採点手順

1. **静的チェック**: `ast.parse` が成功し、`required_ast_nodes`（全て必須）と `required_any_ast_nodes`（いずれか必須）のノードが含まれる。例: ステージ4の合計は `For` または `While` が必須（繰り返しを使わず `n*(n+1)//2` で済ませるのを防ぐ）。
2. **各テストを独立したプロセス／ワーカーで実行**し、全テスト合格で正解。
3. テストの種類:
   - `kind: "stdout"`: `setup + 学習者コード` を実行し、標準出力を 5.4 の正規化後に `expected_stdout` と比較。
   - `kind: "call"`: `setup + 学習者コード` の後で `call` 式を評価し、`repr(結果) == repr(ast.literal_eval(expected))` で比較。`repr` で比べるので `True` と `1`、`5` と `5.0` は区別される。
4. `visible: false` の**非公開テスト**を必ず含める（入力値で結果が変わる問題は3件以上。全体で55件中31件が非公開）。変数の値を決め打ちして `print(15)` と書く不正を防ぐ。
5. `prefix_code`（= 最初の公開テストの `setup`）は画面に読み取り専用で表示する。

### 完全一致を採用しない理由

コード作成問題では、変数名・空白・別解（for/while、if/else の書き方）が自由なため、**文字列の完全一致は使わない**。全問が実行結果ベースの判定で、別解は `answer.alternative_solutions` に用意し、**全て合格することを検証**している（13問すべてに別解があり、合計22個。うち PY-098 の別解の1つは教科書で扱わない `[::-1]` を使用）。不合格例（よくある誤り）は合計26個で、**全て不合格になることを検証**している。

### 検証の実績

各コード作成問題について、(a) 初期コードが不合格、(b) 模範解答が全テスト合格、(c) 別解が全合格、(d) 不合格例（よくある誤り）が不合格、であることを **2通りの実行環境**で確認している。

| 環境 | 実行方法 | 結果 |
|---|---|---|
| CPython 3.12.10 + subprocess | `python src/verify.py` | 全件期待どおり |
| ブラウザ（Pyodide 0.26.4 / Python 3.12.1 の Web Worker） | アプリの `#/selftest` 画面 | 74件（初期コード13＋模範解答13＋別解22＋不合格例26）すべて期待どおり |

### 5.5.1 ブラウザ試作の実装（`app/pyworker.js`, `app/pyrunner.js`）

- Pyodide は初回のみ jsDelivr（`v0.26.4` 固定）から読み込む。**初回はネットワークが必要**。読み込めないときは画面に理由を表示し、自己採点に切り替えられる。
- 採点は「静的チェック（ast）→ テストを1件ずつ新しい名前空間で実行」の順。1件ごとのタイムアウトは `grading.timeout_sec`（5秒）。超過すると Worker を `terminate()` して作り直し、**残りのテストは実行せず不合格**にする（作り直しのたびに約1秒かかるため）。
- 前提コード（`setup`）と学習者コードを連結して `exec` し、`call` 型は `repr(結果) == repr(literal_eval(expected))` で比較（`lib.py` の参照実装と同じ）。
- 非公開テストは、合格数のみ表示して入力値は見せない。
- 実行エラーは `エラー名: 内容（n行目）` の形で学習者コードの行番号を表示する。

## 5.6 実行の安全要件（本番）

学習者のコードは**任意コード**です。サーバーの `exec` で直接実行してはいけません。

| 要件 | 内容 |
|---|---|
| 隔離 | ブラウザ内の Web Worker 上の WebAssembly Python（Pyodide）、またはサーバー側ならコンテナ／gVisor／Firecracker 等のサンドボックス（ネットワーク遮断・非 root・読み取り専用FS） |
| 時間制限 | 1テストあたり 3〜5 秒でタイムアウト（`grading.timeout_sec`）。Worker は強制終了（`terminate()`）して作り直す |
| メモリ制限 | サーバー側は 128MB 程度の cgroup 制限。ブラウザ側は Worker のメモリに依存するため、出力量（標準出力）を 64KB 程度で打ち切る |
| 出力制限 | 無限ループの `print` で画面やメモリを埋めないよう、標準出力のバイト数に上限 |
| 機能制限 | `import` は許可リスト（`random` のみ）。`open`・`input`・`eval`・`exec`・`compile` などを学習者の名前空間から除去。Worker 初期化後に `fetch`・`XMLHttpRequest`・`WebSocket` などを無効化する処理を入れている（**この無効化自体の効果は個別には未確認**。`import js` が許可リストで拒否されることのみ確認）。ただし**完全なサンドボックスではない**。Python の内省機能を使えば回避できる可能性があるため、Worker 隔離（DOM・localStorage に触れない）を主な防御とする） |
| 再現性 | `setup` と学習者コードを毎回新しい名前空間で実行し、前回の状態を持ち越さない |

**ブラウザ試作で実際に確認した項目**（`#/selftest` →「時間切れ・禁止機能のテストも実行」）: 無限ループが時間切れで不合格になり、その後に正しいコードが合格する／`import os`・`import js`・`open` が使えない／`import random` は使える／大量出力が64KBで打ち切られる／テスト間で変数が共有されない（8/8件OK）。**未確認**: メモリを使い切るコード（巨大なリストなど）への耐性、Python の内省による制限の回避、他ブラウザでの動作。

> 検証用の `src/lib.py: run_py` は、`subprocess` + タイムアウトのみの**簡易実行**です。教材データの作者検証用であり、学習者コードの本番実行には使わないでください。

## 5.7 ブラウザ試作向けの代替案（段階的に）

| 段階 | 方式 | 対応できる問題 |
|---|---|---|
| A. 最小 | 選択式・穴埋め・出力予測だけ自動採点。コード作成は**模範解答の表示と自己採点**（「解答例と見比べる」ボタン） | 87問を完全自動、13問は自己採点 |
| B. 推奨 | **Pyodide を Web Worker で実行**し、`test_cases` を採点。タイムアウトは Worker の `terminate()` | 100問 |
| C. 本格 | サーバー側サンドボックスで実行し、結果のみ返す | 100問＋将来の他言語 |

現在のブラウザ試作は **B（Pyodide + Web Worker）を実装済み**で、Pyodide を読み込めない場合のみ A（自己採点）に切り替わります。

## 5.8 採点結果の返し方（推奨レスポンス）

```json
{
  "question_id": "PY-050",
  "correct": false,
  "failed_tests": [{"index": 1, "visible": true, "message": "期待: 1.5 / 実際: 3"}],
  "feedback": "feedback_incorrect の文言",
  "show_explanation": true
}
```

非公開テストが失敗した場合は、入力値を見せず「別の入力でも確かめてみましょう」とだけ伝える。
